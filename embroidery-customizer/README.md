# Embroidery Customizer — 3D T-shirt personalization for Shopify

A Preact + TypeScript + Three.js configurator that lets customers add **text or a logo**, see it
**embroidered onto a rotatable 3D T-shirt** (front and back), add it to the **real Shopify cart**, and
**edit it again from the cart**.

**Features**

- Up to **4 designs per shirt** (left/right chest, upper/center back — overlapping spots are blocked).
- **10 fonts** (3 premium scripts) and **20 thread colours**.
- **5 embroidery styles** rendered in 3D: Flat, 3D Puff, Metallic thread, Woven patch, Chenille.
- **Logo uploads** with one-click **background removal** (keeps white areas inside the logo).
- **Live price on every step** — updates instantly for size tier, premium font, style and every added logo.
- **Team / bulk orders**: one design, a different name + size per person, added in one cart request.
- **Save & share** links that reopen a design; "Your saved designs" list.
- Edit any customized line from the cart; fees stay in sync with quantity changes. Designs and artwork are stored server-side by a Shopify app
(React Router template) and appear on **packing slips** for fulfilment.

```
packages/shared/        Types, model adapters (placements per GLB), validation, serialization
packages/shopify-cart/  Locale-aware Ajax cart adapter, demo cart, line-item property builder/merger
packages/configurator/  Preact UI, Three.js engine (decals, recolour), persistence, Shopify entry + loader
apps/demo/              Standalone Vite demo + local Shopify simulator (mock Ajax cart + app proxy)
extensions/embroidery-customizer/  Theme app extension: app block, cart "Edit" embed, built assets
app/ prisma/            Shopify app backend: app proxy routes, webhooks, admin lookup, Prisma models
packing-slip/           Ready-to-paste packing slip Liquid snippet
models/source/          Original GLB (optimized copy is generated by `npm run model:optimize`)
tests/                  Vitest unit tests + Playwright browser tests
```

The host repository is an existing Online Store 2.0 theme. This folder is self-contained; the theme
itself only received a homepage section (see “Theme-native homepage section” below).

## Quick start (no Shopify account needed)

Requires Node ≥ 20.19 (the Shopify app template recommends Node 22 for production).

```bash
cd embroidery-customizer
npm install
npm run demo          # http://localhost:5173  — standalone demo with a local demo cart
```

- `http://localhost:5173/` — the configurator exactly as embedded in Shopify, demo variants + demo cart.
- `http://localhost:5173/shopify-sim.html` — the **real Shopify code path** (lazy loader, `cart/add.js`,
  `cart/change.js`, app proxy, cart “Edit embroidery” hook) against a local mock store.

```bash
npm run typecheck     # storefront packages + Shopify app
npm run lint
npm test              # Vitest unit tests
npm run test:e2e      # Playwright (desktop + mobile; downloads Chromium on first run: npx playwright install chromium)
npm run demo:build    # static demo build → apps/demo/dist
npm run extension:build   # storefront bundle → extensions/embroidery-customizer/assets
npm run theme:build       # same, and copies it into the host theme's assets/ folder
npm run check         # everything above except e2e
```

## The 3D model

| | |
|---|---|
| Source | `models/source/tshirt-source.glb` (Blender export, 2.11 MB) |
| Served | `apps/demo/public/models/tshirt.glb` and `extensions/embroidery-customizer/assets/embroidery-tshirt.glb` (224 KB) |
| Optimize | `npm run model:optimize` — WebP textures (≤1024px), meshopt + quantized geometry, **no simplification** |

Inspected structure: one mesh (`RetopoMain.004`, 2,841 vertices / 4,970 triangles), packed UV atlas, one
double-sided PBR material with base colour, normal and metallic-roughness maps. Units are metres; the
front faces **+Z** (V-neck at y≈1.677, back neck y≈1.771).

How it is rendered:

- **Original materials and textures are preserved.** Garment colour changes use a shader tint that keeps
  the texture’s shading and the authored white trim / contrast stitching; the normal map (fabric folds)
  and roughness map stay in place. Roughness is remapped ×1.45 into a cotton range (`fabricRoughnessScale`).
- **Embroidery follows the surface.** Designs are rasterized to a transparent canvas (thread colour, satin
  stitch striping, raised shadow) and projected with a custom decal builder that clips the garment’s own
  triangles to an oriented box — so the patch bends with the shirt. The decal also reuses the garment’s
  normal map through a second UV channel, so wrinkles run through the stitching. Back-facing and
  opposite-panel triangles are excluded.
- **Placements** live in `packages/shared/src/models.ts` (normalized garment coordinates + real-world cm
  limits), not in components: left / center / right chest (front), upper back and center back.
  Sleeves are typed but marked *unavailable* until calibrated.

### Model URLs in Shopify

The block resolves the model in this order:
1. The product’s own **3D model media** (upload the GLB in the product’s Media section) — recommended.
2. **Model URL override** setting (e.g. a GLB uploaded to *Content → Files*).
3. The bundled sample `embroidery-tshirt.glb` from the extension’s CDN assets.

A different garment needs its own calibration profile (a new `ModelAdapter`): measure its bounding box,
facing axis and torso area, then add placements — see `TSHIRT_V1` for a commented example.

## Installing on Shopify

### A. Create and run the app (development store)

You need a Shopify Partner account and a development store. Log in when the CLI asks — never paste
credentials into chat or commit them.

```bash
cd embroidery-customizer
npm install
npm run config:link   # create/link the app in your Partner Dashboard (fills client_id in shopify.app.toml)
npm run dev           # shopify app dev — tunnel, DB migration, app + theme extension preview
```

Press `p` in the CLI to open the app and install it on the dev store. The CLI updates the app URL,
redirect URL and **app proxy** (`/apps/embroidery`) automatically during development.

### B. Add the customizer to a product page

1. *Online Store → Themes → Customize* (use a development/duplicate theme first).
2. Open a **product template** → *Add block* → *Apps* → **Embroidery customizer**.
   - In a narrow product column choose *Display → Button that opens a full-screen customizer*;
     or add it to an *Apps* section below the product for the full two-column layout.
3. *App embeds* → enable **Embroidery: edit in cart** (adds “Edit embroidery” to cart lines).
4. Set the *Garment colour map* so your colour option values (e.g. `Navy`) map to hex colours.

The same block can be placed on the **homepage** or any page — pick the product in the block settings.

### Pricing: the “Embroidery fee” product

Prices are never set by the browser. Create one product in Shopify (e.g. **Embroidery fee**, not
shown in collections, no shipping) with a variant per fee you charge — the variant **title** decides
what it's for, the variant **price** is the fee:

| Variant title | Charged when (per item) | Demo price |
|---|---|---|
| `Text` | each text design | $5 |
| `Logo` | each uploaded logo / image | $8 |
| `Medium size` | a design 10–20 cm on its longest side | $3 |
| `Large size` | a design 20 cm or more | $6 |
| `3D Puff` / `Metallic thread` / `Woven patch` / `Chenille` | that embroidery style | $4 / $3 / $6 / $7 |
| `Premium font` | a premium script font | $2 |

Skip any variant you don't charge for. Then choose the product in the block's **Embroidery fee
product** setting (and in the *Embroidery: edit in cart* embed). The live price on every step uses
those Shopify prices, and the fees are added as separate cart lines tied to the shirt (hidden
`_Embroidery Fee For` property). Removing a shirt or changing its quantity in the cart keeps the
fee lines in sync. Size tiers are defined in `packages/shared/src/pricing.ts` (`SIZE_TIERS`).

### C. Packing slips

*Settings → Shipping and delivery → Packing slips → Edit template*: paste
`packing-slip/embroidery-details.liquid` inside the `{% for line_item in line_items_in_shipment %}` loop,
after the item title. It prints type, text/artwork file, font, thread colour, placement, size, adjustments
and the Customization ID (all values escaped). Native packing slips can’t load external images, so staff
download the original artwork from the app’s admin page by Customization ID.

### D. Production

- Host the app (Dockerfile included) and set the env vars below; run `npm run setup` on deploy.
- Use a production database (change the Prisma `datasource` from SQLite to PostgreSQL/MySQL).
- Set `STORAGE_DRIVER=s3` with a **private** bucket (AWS S3 or Cloudflare R2).
- Schedule `npm run cleanup:artwork` daily (deletes designs never ordered after `RETENTION_DAYS`).
- `npm run deploy` builds the storefront bundle and deploys the app + theme extension.

## Theme-native homepage section (already added to this theme)

On request, the homepage (`templates/index.json`) now shows only an **Embroidery customizer** section
(`sections/embroidery-customizer.liquid` + `snippets/embroidery-config.liquid`, assets
`assets/embroidery-*`). The header and footer use the theme’s *Default* design instead of the
“Custom Header/Footer” placeholders. It works **before the app is installed**:

- With no product selected it runs as a labelled **demo** (local demo cart).
  → In the theme editor, open the section and **choose the T-shirt product** before publishing.
- With a product selected, text embroidery adds the real variant to the Shopify cart with line-item
  properties. Logo uploads and cross-device edit-in-cart need the app (app proxy) installed.
- After changing configurator code, refresh the theme copy with `npm run theme:build`.
- Preview with `shopify theme dev` from the theme root, or push to an unpublished theme first.

## Environment variables

See `.env.example`. Secrets stay in your host’s secret store / `.env` (git-ignored).

| Variable | Purpose |
|---|---|
| `SHOPIFY_API_KEY`, `SHOPIFY_API_SECRET`, `SHOPIFY_APP_URL`, `SCOPES` | App credentials (set by `shopify app dev` locally) |
| `STORAGE_DRIVER` | `local` (dev) or `s3` |
| `S3_BUCKET`, `S3_REGION`, `S3_ENDPOINT`, `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY` | Artwork bucket (S3/R2) — **needs configuration** |
| `MAX_UPLOAD_MB`, `RETENTION_DAYS` | Upload limit (server-enforced) and cleanup window |

External services still needed for production: an app host, a production database, an S3-compatible
bucket, and (for public apps) Shopify’s *protected customer data* approval for order webhooks.

## Data flow and security

- Add to cart: artwork → `POST /apps/embroidery/artwork` (type checked by magic bytes, size-limited,
  rate-limited, shop-scoped random key) → `POST /apps/embroidery/configurations` (full server-side
  validation) → `/{locale}/cart/add.js` with readable properties + `_Embroidery Config Ref`.
  No base64 or secrets in the browser or cart.
- App proxy requests are verified with Shopify’s signature (`authenticate.public.appProxy`); webhooks
  with HMAC (`authenticate.webhook`). Scopes: `read_orders` only.
- Edit in cart: re-fetches `cart.js`, finds the line by key or Customization ID (keys change on edit),
  **merges** properties (keeps other apps’/gift-note keys) and calls `cart/change.js`; a variant change
  removes + re-adds the line with the same data.
- `orders/create` links each line to its configuration only if the ref **and** Customization ID match
  (blocks forged properties); ordered artwork is never cleaned up.

## Known limitations

- The sample GLB is a low-poly garment; placement zones are calibrated for this model only. Sleeves
  aren’t calibrated (shown as unavailable).
- The preview is visual only: no embroidery machine files (DST/PES) are generated; uploaded artwork must
  be digitized by the merchant. Stitch appearance, thread sheen and exact colours will differ.
- Garment recolouring is a shader tint of the authored texture; trims/seams keep their authored colour.
- Cart drawers vary by theme: the edit hook finds lines by their visible “Customization ID”. Themes that
  hide properties need `<span data-embroidery-edit-slot="{{ item.key }}"></span>` in the line markup.
  After saving, the page reloads to refresh theme-rendered cart markup.
- Fees are separate cart lines of the fee product (works on every plan). If a customer removes only a
  fee line, the cart hook re-adds nothing — merchants can hide the fee product from the cart edit or
  use Shopify Functions (Cart Transform) on Plus for bundled pricing.
- A 5th design position needs the sleeves calibrated for this model (data model already supports it).
- Team orders personalize one text design per person (choose which one); numbers per player would be
  a small extension of the same rows.
- Rate limiting is in-memory (per instance); use a shared store when scaling horizontally.
- Theme app extensions don’t run in checkout; customization happens before checkout only.
